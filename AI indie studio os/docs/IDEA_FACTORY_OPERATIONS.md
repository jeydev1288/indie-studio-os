# Idea Factory 로컬 운영 준비

이 문서는 Phase 5의 수동 운영과 검사 절차다. 실시간 조사, 자동 실행·저장·스케줄러는 없다. 기존 `research/` 보고서와 `ideas/backlog.md`를 보존한다.

## 저장과 데이터 계약

조사별 보고서는 `research/`에 날짜와 제목을 포함해 저장하고, 기계 검사할 후보는 별도 JSON 파일에 기록한다. 기존 보고서를 자동 변경하지 않는다. 레코드 계약과 샘플은 `ideas/idea-template.json`을 참조한다. 샘플은 가상의 양식이며 조사 사실이나 실제 고객이 아니다.

관찰한 사실은 URL과 확인일을 연결하고, AI 가설·미확인은 별도 기록한다. 평가는 문제의 심각성·빈도, 고객 접근성, 기존 대안의 빈틈, 구현 가능성, 지불 가능성의 다섯 항목이며 각각 1~5 또는 null(미평가)이다. 점수는 이유와 근거가 있어야 하고 하나라도 미평가면 순위 합산을 하지 않는다. 평가의 일관성과 근거 충분성은 사람이 검토한다.

## QA와 중복

`python scripts/idea_factory.py <파일>`로 JSON 구조와 중복 후보를 검사한다. 정확한 정규화 제목 또는 고객+문제 일치만 찾으며, 의미가 비슷한 문구나 번역은 놓칠 수 있다. 발견된 후보는 사람이 검토하며 자동 삭제·병합하지 않는다. 구조 검사 통과는 URL이 실제로 존재하거나 그 주장을 뒷받침한다는 뜻이 아니다.

QA 담당자는 출처를 직접 열어 주장·날짜·가격 조건의 정확성과 신뢰성을 확인하고, 사실·가설 분리, 개인정보, 점수 근거, 미확인 사항, 중복 후보와 최종 권고의 일관성을 검토한다. 미확인은 미확인으로 남긴다.

## 실행 기록과 재시도

각 조사 실행 시 `research/RUN_LOG_TEMPLATE.md`를 복사해 날짜별 로그를 기록한다. 입력, 작업 식별자, 시도 횟수, 산출물, 근거 검토, 성공·실패·중단과 다음 행동을 남긴다. 로그는 자동으로 만들어지지 않는다. 키와 민감정보를 기록하지 않는다.

일시적 네트워크 읽기 실패는 최대 2회 재시도하고 시도 사이 2초 이상 기다린 후 실패를 기록한다. 인증 실패, 잘못된 입력, 승인 부족은 자동 재시도하지 않고 중단한다. 외부 부작용의 성공 여부가 불명확하면 재시도 전에 상태를 확인한다. 이 정책은 운영 지침이며 아직 자동 재시도 코드는 없다.
