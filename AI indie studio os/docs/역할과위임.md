# 역할과 호출 규칙

| 역할 | 책임 | 적합한 기존 도구·스킬 예시 |
| --- | --- | --- |
| Orchestrator | 문맥·질문·분배·승인·검증·보고 | Codex 하위 에이전트, 기존 작업 기록 |
| Researcher | 출처 기반 시장·경쟁 조사 | 웹 검색, studio-market-research |
| Product Manager | 고객 문제·가설·MVP·수익 모델 | studio-product-planning, product-app-architect |
| Engineer | 기존 구조 분석, 구현과 적절한 테스트 | 프로젝트 도구, codex-superpowers |
| QA | 독립적 품질·보안 검토와 재현 | 해당 QA·security 스킬과 실제 실행 환경 |
| Strategist | 경쟁·고객 접근성·사업 가설 비교 | 제품 기획·시장 조사 결과 |
| Designer | 사용자 흐름·시각 구조·접근성 | frontend-design 스킬 |
| Growth | 고객 도달 채널과 실험 가설 | 제품·시장 근거 |
| Analytics | 지표 정의, 데이터 품질 및 분석 | 실제 관측 데이터·지표 스킬 |
| Learning | 재현된 오류와 검증된 개선 기록 | `docs/MISTAKES.md`, 운영 매뉴얼 |

예시는 설치와 권한을 보장하지 않는다. 현재 세션에서 발견된 스킬과 도구를 먼저 확인하고, 없으면 사용 가능한 대안으로 진행한다. 외부 도구 설치가 필요하면 사용자 허락을 받는다. 보안이나 법률 검토 결과를 전문 자문으로 단정하지 않는다.

총괄은 역할 이름을 지정할 수 있는 실행 환경이면 해당 설정을 사용한다. 불가능하면 동일한 역할 계약을 일반 하위 에이전트에 전달한다. 하위 에이전트는 독립된 범위만 맡고, 총괄이 결과를 근거와 함께 확인한다. 대리 위임은 실행 환경의 상위 정책이 허용하는 경우에만 가능하다.

현재 `.codex/agents/`에는 Orchestrator, Researcher, Product Manager, Engineer, QA 설정이 있다. 나머지 역할은 위 지침을 일반 에이전트나 총괄에게 작업별로 전달하는 논리적 역할이다. 이 세션에서는 프로젝트 TOML의 선택·호출을 검증하지 못했다. [워크플로 계약](WORKFLOW_CONTRACTS.md)은 각 역할의 입력과 완료 기준을 정한다.
